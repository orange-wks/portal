fast-jev-compaction (Jev) で Claude Code の compaction を間引きに替えたら 1.4 秒

← orange-wks
llmtypesafeClaude Codecontextengineering2026-09-19

Claude Code の compaction（context が溢れそうなときの会話圧縮）を、組込みの要約から fast-jev-compaction に替えました。Desktop app の session で 187,635 token を 33,447 token（82% 削減）に圧縮するのに 1.4 秒でした。組込みの要約は同じ規模で数十秒かかります。要約文を書かないので、会話本文に書いた file:line や実測値はそのまま残ります。

試した条件

  • 2026-09-19 の 1 日、session 3 本（terminal 2 回、Desktop app 1 回の compaction）
  • Windows 11、Claude Code native 2.1.277（terminal）と Desktop app 同梱 2.1.275
  • 対象 repo は自分の TypeScript プロジェクト。会話は日本語、tool 出力は英語混じり
  • plugin の設定は default のまま

n=3 です。長期運用した結果ではありません。

何をするか

Claude Code の compaction は、context が上限に近づくと会話全体を model に読ませて要約文を書かせ、それを新しい context の先頭に置きます。fast-jev-compaction は要約文を書きません。会話中の tool 呼び出し（Read、Bash、Grep など）とその結果を 1 件ずつ「この先まだ要るか」と判定し、要らないものを削除するか先頭 300 文字に切り詰めます。user と assistant の本文は変更しません。

判定は Jev に投げます。TypeSafe AI が 2026-09-15 に early access で出した、文章を生成しない判定専用 model です。yes / no の質問に較正済み確率で答えます。料金は入力 $0.042 / 1M token、出力は無料、応答は 70〜500 ms です。

Claude Code 側は function hooks（2.1.274 以降、CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 が必要）の session.compact event を横取りする形で入ります。/compact を手で打ったときも auto-compact のときも同じ event が飛ぶので、両方に効きます。Jev への request が失敗したときや削減率が 25% 未満のときは組込みの要約に戻ります。

入れ方

前提は 3 つです。

  • Claude Code 2.1.274 以上（claude --version）
  • 環境変数 TYPESAFE_API_KEY（TypeSafe の early access で取得）
  • 環境変数 CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1

まず 1 session だけで試しました。repo を clone して --plugin-dir で起動します。runtime 依存が無いので npm install は不要です。

git clone https://github.com/tamaratran/fast-jev-compaction /c/dev/fast-jev-compaction
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir /c/dev/fast-jev-compaction

この起動方法だと /plugin の一覧には出ません。動いているかは /compact を打って fast-jev-compaction: で始まる toast が出るかで確認します。会話が短いうちは fallback to built-in summary (below 25% minimum: 0% reduction; no tool calls ...) と出ます。これで hook は通っています。

常用するには user scope で install します。marketplace の出所は local clone にしました。作者の push が勝手に入らず、更新は自分で git pull したときだけです。

claude plugin marketplace add /c/dev/fast-jev-compaction
claude plugin install fast-jev-compaction@fast-jev-compaction --scope user

~/.claude/settings.json に flag を書きます。

{
  "env": {
    "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1"
  }
}

これで新しく開く session すべてに効きます。Desktop app（Claude Desktop の Code tab）は同梱の Claude Code が別 process で動いていて、settings.json と installed plugin を共有します。Desktop app を再起動したら、開きっぱなしだった既存 session にも効きました。

実測

session compaction 前 後 削減 所要
terminal 1 回目 114 message 46 message 86% 記録なし
terminal 2 回目 57 message 49 message 40% 記録なし
Desktop 187,635 token 33,447 token 82% 1,351 ms

terminal の数字は plugin の toast、Desktop の数字は transcript（~/.claude/projects/<repo>/<session>.jsonl）の compact_boundary record から取りました。

terminal 1 回目の内訳は、tool 呼び出し 35 件のうち削除 34 件（Bash 32、Write 1、PowerShell 1）、結果の切り詰め 1 件、原文のまま残したもの 0 件です。Jev が返した「呼び出しを残す」確率は最小 0.19、中央値 0.26、最大 0.50 で、閾値 0.5 を超えたものはありませんでした。「結果を残す」確率は最大 0.20 でした。Jev に送った state は約 14,200 token で、request は 1 回です。

Bash の出力は「再実行すれば戻る」側に判定されています。compaction 後の tool 呼び出し 10 件のうち 3 件は前に打ったものと同じ command でしたが、作業の流れとして打ち直したものと区別がつかず、compaction が原因かは分かりません。

費用は 1 回の compaction で state（上限 25,000 token）を request ごとに再送します。1 request に入る質問は約 80 問（tool 呼び出し 40 件分）です。

tool 呼び出し数 request 数 送信 token 費用
40 1 約 28k $0.001
150 4 約 115k $0.005
400 10 約 290k $0.012

注意点

日本語で token 推定が外れる可能性があります。 plugin の token 見積りは非 ASCII 1 文字 = 0.9 token で、英語で較正されています。Jev の tokenizer が日本語をこれより細かく刻む場合、推定 25k が実際には 32k の上限を超えて 4xx になり、組込み要約に fallback します。今回の 3 回は state が 14k 以下で当たりませんでした。当たった場合は toast に Jev request failed (4xx) と出るので、user settings の pluginConfigs["fast-jev-compaction@fast-jev-compaction"].options.maxStateTokens を下げます。

/compact 〇〇を残して の指示は読まれません。hook は event.instructions を参照していません。

Bash の出力に出た実測値は、上の結果のとおりほぼ消えます。残したい数字は assistant の本文に書かせるか、file に落とします。本文は削られません。

plugin 独自の auto-compact が context 60% で走ります（組込みは 90% 台）。本文だけで 60% を超えた session では、削るものが無く 25% 未満で fallback し、組込み要約が標準より早く走ります。手動 /compact だけにしたい場合は compactAtPercent を 999 にします。

直近 6 message（tool 往復 3 回分）は判定対象外です。4 回前に Read した file は削除されうるので、再 Read が 1 回増えます。

画像の tool 結果（screenshot など）は text が空扱いで、削除されると画像ごと消えます。組込み要約でも消えるので現状維持です。

--resume や Desktop app の session 復元で、圧縮後の状態が transcript に永続化されるかは確認していません。

止めるときは claude plugin disable fast-jev-compaction@fast-jev-compaction です。
